# Product specs

User/product requirements for lunchbox: who uses it, what jobs it does, and
the acceptance criteria for each capability. Empty until the `DESIGN.md`
review extracts them.

Specs are the narrative; `../feature-list.json` is the executable contract.
When a spec defines independently testable behavior, it gets a feature entry
there, and the feature passes only when its listed checks succeed.
